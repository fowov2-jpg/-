# Графика Управдома · Blender 4.3.2

В `source/` находятся три самостоятельных редактируемых проекта:

- `municipal-fleet.blend` — 17 машин в отдельных именованных коллекциях; кузова, колёса, остекление, шасси, оборудование и материалы сохранены отдельными объектами.
- `neighborhood-library.blend` — десять дворовых сцен: жилые дома, высотки, кирпичные кварталы, промышленная и прибрежная застройка. Используются как иллюстрации в сведениях о доме.
- `worksite-props.blend` — рабочие трёх служб, четыре позы шага, каски, отражающие полосы, ограждения, конусы, насос, генератор, инструмент, кабельная катушка и опоры техники.

Геометрия написана для проекта. Пропорции и окраска машин ориентируются на фотографии владельца из `docs/vehicle-references`; это художественные модели, а не заводские CAD. Исходная карта `web/assets/districts` и базовое оформление `web/campaign-ui.css` сохранены. Файлы `.blend` не входят в APK.

Игра использует прозрачные изображения, полученные в Blender Cycles, поверх прежнего города. Это позволяет сохранить офлайн-работу и управление Canvas на Android. Карта не заменена полноценным трёхмерным движком.

## Воспроизведение экспорта

Нужны официальная сборка Blender 4.3.2 с CPU OpenImageDenoise, Python 3 и Pillow. Системная сборка Blender без денойзера для этих настроек не подходит. Команды запускаются из корня репозитория; каталог экспорта можно выбрать произвольно:

```sh
blender -b -t 3 --python art/blender/build_fleet.py -- --output art/blender/build --sprites --mechanisms
blender -b -t 3 --python art/blender/build_neighborhoods.py -- --output art/blender/build
blender -b -t 3 --python art/blender/build_props.py -- --output art/blender/build
python3 art/blender/pack_assets.py --input art/blender/build
```

Результат: исходники в `art/blender/build/source/`, исходные PNG в `raw/`, WebP в `web/assets/blender/`, координаты камер и обрезанных кадров в `web/blender-manifest.js`. Для обновления сохранённых редактируемых проектов скопируйте новые `.blend` из `build/source` в `source`.

`build_fleet.py --only uaz39094-utility --preview` даёт крупный пробный рендер. `--resume` у техники и кварталов продолжает прерванный экспорт с прежними настройками, пропуская существующие PNG. Кварталы рендерятся отдельными процессами, затем собираются в общий проект без повторного рендера; это ограничивает память Cycles. После изменения геометрии, света или камеры удалите соответствующие старые кадры перед повторным запуском. `pack_assets.py --partial` предназначен только для локального просмотра; финальный экспорт без этого флага отказывается принимать неполный набор.

Масштаб сцены — метры, Z направлен вверх, перед машины — +Y. Корпус имеет 16 направлений с постоянным мировым освещением. Девять механизмов экспортируются отдельным слоем: пять положений раскладывания и восемь направлений; центр поворота сохраняется в метаданных. Поворот корпуса и наведение верхней части разделены. Сборщики пересоздают геометрию из кода; ручные правки в `.blend` сохраняйте отдельно и переносите в сборщик перед повторным экспортом. Исходники сохраняют отдельные детали; положения оборудования задаёт функция `mechanism()` в `build_fleet.py`. В `.blend` нет скелетной анимации.

Упаковщик обрезает прозрачные поля и убирает слабый шум shadow catcher. Он сохраняет исходную точку камеры каждого кадра, включая точки вне обрезки. Страницы ограничены 2048 × 2048; PNG и промежуточные Blender-файлы не поставляются в приложение. Насос, инструмент и рабочие используют собственный атлас. Маячки, гибкие шланги и провода рисуются в игровом слое и используют игровое время.

## Проверка

```sh
npm test
CHROMIUM_PATH=/usr/bin/chromium npm run test:graphics
CHROMIUM_PATH=/usr/bin/chromium npm run test:motion
CHROMIUM_PATH=/usr/bin/chromium npm run test:performance
```

Проверяются полнота набора, координаты обрезки, память текстур, все 17 машин в 16 направлениях и девяти положениях, включая промежуточные между экспортированными кадрами, гараж, совместный выезд, сведения о доме, пауза и повторный запуск на ширине 344/412/960. Скриншоты сохраняются в `test-results/blender`. Эти проверки подтверждают работу экспорта и интерфейса; художественную приёмку определяет владелец при прохождении игры.
