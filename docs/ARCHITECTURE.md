# Архитектура

## Модель

Состояние версии 2 (загрузка версии 1 с миграцией): день, минута, phase, бюджет, репутация, PRNG seed, дома, бригады, обращения, журнал, отчёт. Детерминированное ядро `engine.js` не зависит от UI и реального времени. Каждая команда проверяет допустимость перед изменением денег и назначения. Однопоточный tick обновляет симуляцию по целым игровым минутам.

Состояния смены: prep → active → report → prep. Состояния заявки: new → travel → diagnosis → repair → done; альтернативно new → contractor → done. Бригада освобождается только после завершения. В конце смены активные назначения не удаляются.

## Представление

Vanilla JS ES modules, CSS и Canvas 2D. Детализированный локальный фон `web/assets/neighborhood.webp` занимает около 690 КБ. Canvas рисует поверх него адреса, заявки, маршруты и машины. Геометрия дорог и точки домов заданы в координатах карты 1000×1500. `roads.js` находит кратчайшие пути по графу; та же длина определяет время поездки в ядре. Это пререндеренная сцена с динамическим игровым слоем, а не 3D-модель зданий.

Симуляция обновляется раз в секунду. Карта интерполирует движение отдельно, с ограничением до 25 кадров в секунду и DPR до 2. В фоне, на других вкладках и при отключённой анимации ненужные перерисовки не выполняются. Интерфейс содержит пять разделов: карта, заявки, бригады, финансы, гараж. Состав сотрудников фиксирован; рабочие параметры агрегированы в бригаду.

## Сохранение

Основной ключ localStorage — `upravdom.v1`, резервный — `upravdom.backup.v1`. Версия схемы внутри JSON — 2; версия 1 мигрирует при загрузке. Проверяются числовые поля, дома, бригады, заявки, взаимные ссылки назначений, журнал и отчёт.

Перед записью состояние валидируется. Предыдущее корректное основное сохранение записывается в резервный ключ перед заменой основного. Если основной файл повреждён или отсутствует, используется резервный. При повреждении обеих копий или недоступности хранилища автосохранение блокируется до подтверждённого сброса или импорта. Старые данные не затираются при навигации и выходе.

Экспорт JSON и импорт с валидацией и отдельным подтверждением доступны в настройках. Настройки звука, анимации и подписей хранятся отдельно. Фоновое время не начисляется. Автосохранение не заменяет внешнюю копию: очистка данных приложения удаляет оба локальных ключа.

Бюджет `opening` фиксируется перед подготовкой каждого дня. Результат смены включает профилактику, ТО, оснащение и обучение до запуска смены, а также все операции во время работы. Журнал хранит последние 100 операций.

## Android

Activity на Java 17, WebViewAssetLoader отдаёт только упакованные assets через https://appassets.androidplatform.net. File/content access отключены, mixed content запрещён, сетевого разрешения нет, неизвестные запросы отклоняются. JS bridge не используется. Импорт открывает системный ACTION_OPEN_DOCUMENT через WebChromeClient; экспорт — ACTION_CREATE_DOCUMENT по локальному navigation intent. Передача экспорта допускается только из главного фрейма доверенной локальной страницы. Доступ ко всему хранилищу не запрашивается. Браузерный и Android-режимы используют одни исходники `web/`, копирование на этапе сборки не нужно.

Пауза Activity отправляет событие upravdom-pause и сохраняет игру. Android Back закрывает карточку или сворачивает приложение. Системные отступы обрабатываются нативно. Проверка жестовой навигации и lifecycle на устройстве обязательна до релиза.

Документация подхода: https://developer.android.com/develop/ui/views/layout/webapps/load-local-content

## Сборка и тесты

`npm test` не устанавливает пакеты и запускает встроенный node:test. GitHub Actions: unit tests → Gradle assembleDebug и lintDebug → APK artifact. Android SDK/Gradle локально в среде автора не установлены; готовность CI не равна факту успешной Android-сборки. Release signing, AAB и публикация отдельно.

## Развитие без переписывания ядра

1. Перевести контент TYPES в JSON со схемой и локализуемыми строками.
2. Добавить сущности Employee, Vehicle, Inventory и Contract, сохранить Crew как назначение людей и машины.
3. Ввести явные команды и события для повторов и debugging.
4. Дополнить дорожный граф закрытиями и пробками.
5. Миграции сохранений до каждого изменения схемы.
6. Сервис тендеров и конкуренты используют те же команды экономики; отдельного backend пока не требуется.
